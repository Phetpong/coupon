# ระบบจ่ายคูปอง

PHP แบบไม่ใช้เฟรมเวิร์ค + MySQL สำหรับเจ้าหน้าที่ ใช้งานบนมือถือได้

## ติดตั้งบน Plesk

1. นำไฟล์จาก repository ไปยัง document root ของเว็บไซต์ เช่น `httpdocs`
2. ใช้ PHP 8.1 ขึ้นไป เปิดส่วนขยาย `pdo_mysql` และ `mbstring` และใช้ฐานข้อมูล MySQL 8 ขึ้นไป
3. สร้างฐานข้อมูลและผู้ใช้ฐานข้อมูลใน Plesk แล้ว import ฐานข้อมูลที่คุณ export จากเครื่องเดิมด้วยตนเอง โดยนำทั้ง `staff` และ `coupons` ไปด้วย
4. คัดลอก `.env.example` เป็น `.env` แล้วระบุข้อมูลเชื่อมต่อของเซิร์ฟเวอร์จริง ห้าม commit `.env` หรือไฟล์ export ฐานข้อมูล
5. เปิด HTTPS และตั้ง `display_errors=Off`, `log_errors=On` ใน PHP settings
6. ตรวจการเข้าสู่ระบบด้วยบัญชีที่ import มา `phet` เป็น admin ส่วนบัญชีอื่นเป็น officer

ไฟล์ SQL และไฟล์ export ฐานข้อมูลไม่รวมอยู่ใน repository ให้เก็บและ import แยกผ่านช่องทางส่วนตัว ห้ามเพิ่มกลับเข้า Git

### ปิดการเข้าถึงไฟล์ภายใน

Apache ใช้กฎใน `.htaccess` ที่แนบมา หาก nginx ให้บริการไฟล์โดยตรงหรือใช้ nginx-only ให้เพิ่มกฎใน Additional nginx directives ด้วย:

```nginx
location ~ /\.(?!well-known/) { deny all; }
location ~* \.(sql|zip|gz|log|bak|md)$ { deny all; }
location ~ /(?:config|app|header|user-management|analytics-data)\.php$ { deny all; }
```

ตรวจว่า URL `/.env`, `/schema.sql` และ `/.git/config` ตอบ 403 หรือ 404 ก่อนใช้งานจริง หากติดตั้งใน subfolder ให้เติม subfolder ใน URL ที่ทดสอบ

อ้างอิง: [Plesk — ป้องกันการเปิดไฟล์ผ่านเบราว์เซอร์](https://support.plesk.com/hc/en-us/articles/12377449997591-How-to-prohibit-access-to-a-particular-file-from-a-browser-in-Plesk)

## การทำงาน

- เลขบัตรและชื่อที่ปรับช่องว่าง/คำนำหน้าแล้วรับได้ครั้งเดียวต่อ `EVENT_KEY` ตรวจด้วย unique index ในฐานข้อมูล
- ชื่อซ้ำแต่เลขบัตรต่างกันต้องให้ผู้ดูแลตรวจสอบก่อน ไม่มีปุ่มข้าม
- เลือกกลุ่มก่อนเลือกฟาร์ม/ซุ้ม/หน่วยงาน หรือเลือกเพิ่มชื่อใหม่ ชื่อที่บันทึกแล้วจะแสดงในกลุ่มเดียวกัน
- รายชื่อหน่วยงานมาจากผู้เข้าร่วมที่บันทึกแล้ว หากไม่มีผู้เข้าร่วมจะไม่มีชื่อเดิมให้เลือก
- จำนวนผู้รับแสดงเทียบจำนวนของกลุ่ม แต่ยังไม่บล็อกโควตาต่อหน่วยงาน
- เจ้าหน้าที่เห็นเลขบัตรเต็ม ประวัติกรองตามกลุ่ม/หน่วยงาน ค้นหา และแบ่งหน้า 10/25/50 รายการ
- `phet` จัดการผู้ใช้ได้ บัญชีใหม่เป็น officer ลบ admin หรือผู้ใช้ที่มีประวัติจ่ายคูปองไม่ได้
- เมนูแอดมิน → วิเคราะห์ข้อมูล: สรุปยอดตามงานปัจจุบัน กรองวันที่ (รวมวันสิ้นสุดตามเวลาไทย) กลุ่มและเจ้าหน้าที่ ดูแนวโน้ม 14 วันที่มีการจ่ายล่าสุด และรายละเอียดแยกกลุ่ม/หน่วยงาน/เจ้าหน้าที่/วันพร้อมแบ่งหน้า หน่วยงานไม่ระบุไม่นับในจำนวนหน่วยงาน แต่ยังรวมในยอดผู้รับทั้งหมด
- `.env` อ่านค่าตรงตัว รองรับค่าครอบ single/double quotes และคอมเมนต์แยกบรรทัด ค่า environment ของเซิร์ฟเวอร์มีลำดับก่อน `.env`

## ชุดไฟล์สำหรับใช้งานจริง

ลบสคริปต์สร้าง/ล้างข้อมูลตัวอย่าง สคริปต์ติดตั้งและย้ายข้อมูลเก่า ชุดทดสอบ และ ZIP เก่าออกแล้ว ข้อมูลตัวอย่างและตารางติดตามตัวอย่างถูกล้างจากฐานข้อมูลเครื่องเดิม ไม่แนบข้อมูลส่วนบุคคลหรือรหัสผ่านใน repository

## ประวัติการใช้งานระบบ (รุ่นแรก)

ก่อนเปิดใช้โค้ดรุ่นนี้ ให้รัน migration ผ่าน CLI ด้วย PHP ของเว็บไซต์ (บน Plesk ใช้ executable ของ PHP เวอร์ชันที่เลือก):

```sh
php scripts/migrate-audit.php
```

- ใช้ฐานข้อมูลจาก `.env` เดิม เพิ่มเฉพาะตาราง `audit_logs` แบบ InnoDB รันซ้ำได้ ไม่สร้างฐานข้อมูลใหม่ ไม่ลบข้อมูลเดิม และไม่แนบไฟล์ SQL
- ควรรัน migration ก่อนสลับโค้ดใช้งานจริง เพราะการเข้าสู่ระบบสำเร็จ การจ่ายคูปอง และการแก้ไขบัญชีต้องเขียนประวัติได้
- หากต้องย้อนเวอร์ชัน ให้ย้อนเฉพาะโค้ดและเก็บตาราง `audit_logs` ไว้ ห้ามล้างประวัติเพื่อย้อนรุ่น
- เมนูแอดมิน → ประวัติการใช้งาน (`audit.php`): ดูได้เฉพาะ `phet` ที่มีสิทธิ์ admin กรองวันเวลา เจ้าหน้าที่ หมวด และผลลัพธ์ พร้อมแบ่งหน้า 10/25/50
- บันทึกการเข้าสู่ระบบสำเร็จ/ไม่สำเร็จ ออกจากระบบ จ่ายคูปอง/ข้อมูลซ้ำ เพิ่ม/แก้ไข/เปลี่ยนรหัสผ่าน/ลบบัญชี และการปฏิเสธสิทธิ์หรือ CSRF ไม่เก็บการเปิดหน้าปกติและการค้นหา
- ประวัติครอบคลุมทุกงาน โดยเก็บ `event_key` ณ เวลาเกิดเหตุ แสดงเวลาไทย และชื่อ/username/สิทธิ์ในขณะนั้นแม้บัญชีถูกลบภายหลัง
- การจ่ายคูปองและ CRUD ผู้ใช้บันทึกพร้อมประวัติใน transaction เดียวกัน หากเขียนประวัติไม่ได้จะ rollback ข้อมูลหลัก ส่วนการปฏิเสธและออกจากระบบยังดำเนินต่อได้เมื่อ audit ล้มเหลว โดยแจ้งเฉพาะรหัสข้อผิดพลาดใน server log
- เก็บเฉพาะค่า name/username ก่อน–หลัง ไม่เก็บ password, hash, token, `.env`, ข้อมูลทั้งฟอร์ม หรือเลขบัตรเต็ม เก็บ IP จาก `REMOTE_ADDR` โดยไม่เชื่อถือ forwarded headers ที่ผู้เรียกส่งเอง (หลัง reverse proxy อาจเป็น IP ของ proxy)
- ไม่มี API แก้ไข/ลบ log ไม่มีการลบอัตโนมัติ และไม่สร้างประวัติย้อนหลัง ทั้งนี้ผู้ดูแลฐานข้อมูลยังแก้ไขตารางได้ รุ่นนี้ไม่ใช่ระบบ log ที่ป้องกันการแก้ไขระดับฐานข้อมูล
- หลังติดตั้ง ตรวจล็อกอิน เปิดหน้าประวัติ และทดสอบรายการที่อนุญาต ตรวจว่า URL `/scripts/migrate-audit.php` ตอบ 404 และเจ้าหน้าที่ทั่วไปเปิด `/audit.php` ได้เพียง 403
